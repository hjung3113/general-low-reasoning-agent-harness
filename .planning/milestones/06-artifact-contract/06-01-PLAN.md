# Milestone 06 — Artifact contract

Make `harness/manifest.json` the operational source of truth. Generate `docs/ARTIFACTS.md` from it. Require every removed artifact to carry an explicit upgrade action. **No inference theater** — installed files, generated files, project-owned files, and obsolete files must be visible from manifest data and enforced by tests.

Co-designed with codex via cmux on 2026-05-23 in parallel with M5 sonnet execution. Order: **#17 → #14 → #15** (#17 is a small isolated UX patch; do it first to reduce pain while #14/#15 expose artifact drift).

## #17 — Managed-block conflict diff

**New file / addition.** Add `_managed_append_conflict_diff(destination, plan, entry) -> str` in `scripts/lib/append_block.py` around line 147, using `difflib.unified_diff`. On `write_managed_append()` conflict at line 150, print the unified diff to stderr **before** raising `SystemExit`. Diff compares current managed block (when parse succeeds) vs `plan.proposed_block`; for malformed markers, fall back to whole-file current vs proposed block and label clearly.

**Refactor.** `append_block.py` grows slightly, ~227 → 250–280 LOC unless conflict reporting moves to a separate helper. **Do not change merge semantics** in this issue — conflict still refuses to write. Prefer re-reading destination inside the helper over extending `AppendBlockPlan` with `conflict_reason` / `current_text`; this is a UX patch, not a plan-model churn.

**Call-site cascade.** Primary caller: `scripts/lib/install.py::install()` via `write_managed_append()`. Upgrade likely uses `plan_managed_append()` directly through reconciler paths; **do not** force upgrade to print diffs unless tests reveal the same unhelpful error. `scripts/uninstall_harness.py` uses `plan_managed_append_retirement()` — leave alone unless retirement conflicts have the same complaint. No CI / pre-commit config change.

**Test fallout.** Add focused tests in `scripts/tests/test_append_block.py` (create if absent): malformed managed-append destination exits nonzero and stderr contains `--- current:` / `+++ proposed:` plus marker lines; edited managed-block conflict prints a diff and still refuses; no-conflict path writes without stderr diff. Existing install tests need assertion edits only if they assert the exact `SystemExit` string.

**Order within.** Write failing stderr-diff tests, add helper, wire into `write_managed_append()`, run append-block / install focused tests. Gate: conflict must still refuse to write; diff output is **additive only**.

**Risk + canary.** Risk is leaking huge file contents to stderr or changing conflict behavior. Cap the diff or diff only the managed block when parse succeeds; for malformed full-file fallback, use enough context to diagnose but avoid megabytes. Canary: a malformed `AGENTS.md` install still exits nonzero, leaves the file untouched, and stderr includes a useful unified diff.

## #14 — Generate `docs/ARTIFACTS.md` from manifest

**New files.** Create `scripts/generate_artifacts_doc.py` as the sole generator and create the generated `docs/ARTIFACTS.md`. Do **not** delete `docs/INSTALL-MODEL.md`; replace any hand-maintained artifact tables in it with a short pointer to `docs/ARTIFACTS.md`. Generated doc includes: manifest version, counts by policy, installed-files table (path, policy, source, owner, profile, pack, adapter), pack table (pack, category, suggests, capabilities summary), and a generated-but-timestamp-free footer. **No wall-clock timestamps** in generated output (they produce noisy diffs).

**Refactor.** No runtime LOC should change except optional helper reuse in `scripts/lib/manifest.py` if parsing logic is duplicated. Generator ~180–260 LOC: JSON load, stable sort, Markdown escaping, table rendering, `--check` mode. If `manifest.py` already has typed `ManifestEntry` loading, use it for files and read raw JSON only for packs / `removed_in_version`. **Do not invent a second manifest parser** with subtly different validation.

**Call-site cascade.** Wire into existing test surface (no `.pre-commit-config.yaml` or `Makefile` today): add `scripts/tests/test_artifacts_doc_generated.py` that runs the generator in `--check` mode. Optionally add `scripts/harness.py check` self-check only if that command already aggregates repo-consistency checks. If GitHub Actions has a test job, add `python3 scripts/generate_artifacts_doc.py --check` there; if only release workflow exists, rely on pytest. Update `docs/ARCHITECTURE.md` and `docs/INSTALL-MODEL.md` references that currently describe manifest contents manually.

**Test fallout.** Tests for deterministic generation: running generator twice produces byte-identical output; `--check` passes when `docs/ARTIFACTS.md` is current; mutating a temp manifest changes generated text and causes check failure. Edit docs tests / grep gates only if they complain about generated-file headers. **No tests should assert hard-coded manifest line counts** (like "1357 lines") after this; replace with generated counts.

**Order within.** Build generator for current files / packs only, generate doc, add check test, then update docs pointers. Gate: `python3 scripts/generate_artifacts_doc.py --check` must fail on stale docs and pass after regeneration.

**Risk + canary.** Risk is creating a generated doc nobody regenerates or a generator that silently disagrees with installer selection logic. Canary: file counts in `docs/ARTIFACTS.md` exactly match `harness/manifest.json`; profiles / packs / adapters visible enough to debug install output; `--check` catches drift; no generated timestamps.

## #15 — Graveyard + obsolete-artifact upgrade policy

**Targets / new fields.** Extend `scripts/generate_artifacts_doc.py` and `docs/ARTIFACTS.md` with a **Graveyard / Removed Artifacts** section sourced from `manifest.removed_in_version`. Add fields to manifest entries if missing: `path`, `removed_in_version`, `policy` or `former_policy`, and required `upgrade_action: delete | ignore | warn` with optional `reason`. If current `removed_in_version` only has bare paths, **upgrade the manifest schema now**; do not hide policy in prose.

**Refactor.** Refactor `scripts/lib/upgrade.py` obsolete handling to consume the manifest graveyard instead of hard-coded scattered checks, if such hard-coding exists. Expected: `upgrade.py` should not grow; move toward a small helper `obsolete_artifact_policy(manifest) -> dict[path, action]` in `scripts/lib/manifest.py` or `manifest_reconciler.py`. If upgrade currently does not handle removed artifacts, add minimal behavior: delete harness-owned obsolete files, ignore absent files, warn on project-owned / unknown obsolete files, and **never auto-delete project-owned content**.

**Call-site cascade.** `scripts/lib/upgrade.py::upgrade()`, `scripts/lib/manifest.py` loading/validation, `scripts/lib/manifest_reconciler.py` if it classifies planned removals, `scripts/uninstall_harness.py` only if it reads removed entries, and `docs/INSTALL-MODEL.md` obsolete-artifact prose. CI / pre-commit stays the same as #14: generator `--check` plus tests. If installed-manifest.json records files removed from new manifest, upgrade uses graveyard policy to decide delete/ignore/warn, not infer from path names.

**Test fallout.** Unit tests for graveyard doc generation from `removed_in_version`. Upgrade tests with a temp target containing: obsolete harness-owned file → deleted; obsolete file absent → no-op; obsolete project-owned or unknown policy → warning and preserved; obsolete managed-append block → block retired only if installed hash matches, otherwise conflict/warn. Rewrite tests that currently assert "removed files are just ignored" if that contradicts the new policy. Delete stale tests mentioning audit-chain / state-trust / phase-txn recovery artifacts as retained after M4.

**Order within.** After #14 generator exists, first extend manifest schema for removed entries and make generator **fail loudly** if `upgrade_action` is missing. Then update `docs/ARTIFACTS.md` graveyard output. Then wire upgrade behavior to the same manifest data. Then update tests / docs. Gate: every `removed_in_version` entry has an explicit action, and upgrade tests prove the action is honored.

**Risk + canary.** Risk is deleting user-owned files because a path once belonged to the harness. Default unknowns to **warn**, not delete; only delete entries explicitly harness-owned or installed-manifest-owned. Canary: upgrade from a fixture with obsolete harness files removes only intended paths, preserves user-edited files, prints actionable warnings, and `docs/ARTIFACTS.md` graveyard matches manifest exactly.

## TL;DR

`harness/manifest.json` becomes operational source of truth. Generate `docs/ARTIFACTS.md`, enforce with `--check`, require every removed artifact to carry an explicit upgrade action. Order #17 → #14 → #15. Hard rule: **no inference theater** — installed files, generated files, project-owned files, and obsolete files must be visible from manifest data and enforced by tests.
