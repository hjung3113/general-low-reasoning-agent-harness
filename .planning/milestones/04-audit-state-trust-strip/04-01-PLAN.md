# Milestone 04 — Audit + state-trust strip

Strip crypto/trust/recovery ceremony from the harness's audit + state machinery to match ADR-0002 / ADR-0004 / ADR-0005. The standing decisions explicitly bound this work: no attacker model, no tamper oracle, no hash chain, no recovery matrix. Keep the primitives that prevent normal internal-tool damage from concurrent runs or local write crashes (primary lock + atomic write), and remove everything else.

Co-designed with codex via cmux on 2026-05-23. Both agents agreed on scope and order. Hard gates before merge are listed per issue.

## Scope and order

Sequence is mandatory: **#8 → #9 → #10 → #11**. Treat #8/#9 as one audit-contract strip and #10/#11 as one state-contract strip for execution review.

Hard gates between issues:
- After #9: `audit_append()` still produces readable JSONL and all phase approve/reopen flows still write audit rows.
- After #10: `rg "state_trust|StateAuditMismatch|run_state_trust_preflight|skip_state_trust_preflight"` returns only ADR / history / graveyard references.
- After #11: `phase_txn.commit_transaction()` still preserves atomic state write under lock, and no `recover()` API remains unless a real caller still needs it.

## #8 — Delete `audit_chain.py`

**Targets.** Delete `scripts/lib/audit_chain.py` entirely: `GENESIS_HASH`, `_canonical_bytes`, `_HASH_EXCLUDED_FIELDS`, `compute_entry_hash()`, `stamp_chain_fields()`, and exports. Delete chain-specific fixtures under `tests/fixtures/audit/*` that only verify `entry_hash` / `previous_entry_hash` continuity. Strip stale references in `docs/ARCHITECTURE.md`, `docs/MODULE-MAP.md`, `docs/SECURITY-INVENTORY.md`, `docs/TESTS.md`, and dependency guard references to `rfc8785`.

**Refactor.** `scripts/lib/audit.py` loses all imports of `audit_chain`, all chain-tip computation, and all chain stamping. Combined #8/#9 should take `audit.py` from ~535 LOC to roughly 230–300 LOC. `pyproject.toml` loses stale audit canonicalization / state-trust comments; dependency tests stop treating `rfc8785` as required if nothing else imports it.

**Call-site cascade.** Direct importers: `audit.py` and `tests/audit/test_chain_writer.py`. Indirect: `phase_txn._audit_tail_partial_write()` currently treats `entry_hash` as a mandatory TXN field. After #8 the only audit identifiers that matter are normal JSON fields (`txn_id`, `before_sha256`, `after_sha256`, `verb`, `at`).

**Test fallout.** Delete `tests/audit/test_chain_writer.py` and any dep-guard case requiring `rfc8785` via `audit_chain`. Rewrite `scripts/tests/test_audit.py` assertions so appended rows have plain JSONL fields; no chain fields. Keep tests proving `audit_append()` appends one line, validates known verbs, truncates oversize detail predictably, handles concurrent append.

**Order within.** Delete tests first (or mark expected failures), then remove `audit_chain.py`, then simplify `audit.py` imports/stamping, then run focused audit tests. #8 must precede #9 because `audit.py` currently delegates core row shaping to chain helpers.

**Risk + canary.** Hard-to-undo risk is accidental deletion of useful audit row metadata relied on by `check.py`, `phase_txn.py`, or phase UI. Canary: `rg "entry_hash|previous_entry_hash|audit_chain|rfc8785"` returns only ADR / history / graveyard references; `phase.approve` / `phase.reopen` tests still find audit rows with verb, actor, target phase, and outcome.

## #9 — Simplify `audit.py` to plain JSONL

**Targets.** Remove rotation-seam logic in `_rotate()` that creates `audit.rotated` rows and `next_file_seed_previous_entry_hash`. Remove `_read_chain_tip()` entirely. Remove `_compute_entry_hash_for_minimal()`. Remove chain-aware overflow fallback fields at `scripts/lib/audit.py:487`. Explicit decision: **delete `audit_rotation.py` too** unless a test demonstrates logs realistically crossing `ROTATION_BYTES` / `ROTATION_ENTRIES`; 60 LOC is not worth keeping as a second audit contract.

**Refactor.** Keep `compute_state_hash()`, `read_last_entry()`, `_open_append_fd()`, basic file lock behavior, known-verb validation, line-size fallback if useful, and `audit_append(entry, *, audit_path) -> int`. Slim `audit_append()` to: copy entry, stamp schema_version, seq/index, `at` if absent, JSON-encode compactly, append under lock, fsync, return index. Expected size: `audit.py` ~180–240 LOC if rotation is deleted, ~230–300 if simple rotation stays.

**Call-site cascade.** Update `scripts/lib/check.py` if it reads audit tail `after_sha256` for drift reporting; after #10 that check likely becomes informational or goes away. `install.py`, `install_recovery.py`, `phase_lock.py`, `phase_txn.py`, `phase_approve.py`, and `phase_reopen.py` should not change their call shape unless they were passing chain-only fields; they should keep emitting plain diagnostic entries. Any docs saying `audit.log` rather than `.harness/audit.jsonl` need one naming pass.

**Test fallout.** Delete rotation-seam tests if rotation goes; rewrite `scripts/tests/test_audit.py::test_rotation_*` to either disappear or assert simple file rollover without seam rows. Keep append, read-last-entry, state-hash, known-verb, oversize-entry, and concurrent-writer tests with assertion edits removing chain fields. Delete fixture tests for `duplicate_seq_global`, `rotation_seam_mismatch`, `mixed_v1_v2_rotation_ok`, and `tampered_tail` if their only purpose is chain verification.

**Order within.** After #8: first pin the new plain JSONL shape in tests, then reduce `audit_append()`, then remove rotation if chosen. Do not touch `phase_txn` in this issue except to stop expecting `entry_hash` from audit rows.

**Risk + canary.** Risk is breaking real audit writers by shrinking the accepted verb schema too aggressively. Canary: fresh install + one phase transition produces `.harness/audit.jsonl` with parseable one-line JSON entries, and no test expects cryptographic continuity.

## #10 — Strip `state_trust.py`

**Targets.** Delete `scripts/lib/state_trust.py` entirely: all `StateTrust*` exceptions, `_canonicalize_state_bytes()`, `_most_recent_txn_entry()`, audit-rotation walkback, baseline-state heuristics, and `preflight()`. Delete `phase_preflight.run_state_trust_preflight()` and `StateTrustPreflightError`, or replace with a much smaller `validate_phase_state_file()` only if callers still need JSON / schema error mapping.

**Refactor.** `phase_approve.run_approve()` currently calls `_state_trust.preflight()` directly around `scripts/lib/phase_approve.py:453`; remove the preflight block and the `skip_state_trust_preflight` parameter unless tests need temporary compatibility. `phase_reopen.run_reopen()` calls `phase_preflight.run_state_trust_preflight()` around `scripts/lib/phase_reopen.py:211`; delete that call. `status_next_cli.py` should stop importing `state_trust` and treat status as read-only JSON load plus ordinary parse errors.

**Call-site cascade.** Update `phase_preflight.py` exports and tests; remove compatibility imports `_state_trust` in `phase_approve.py` / `phase_reopen.py` that exist only for monkeypatch tests. `docs/error-code-map.md` loses exit-10 state-audit-mismatch and exit-14 state-empty-crash-artifact references if no replacement path exists. `scripts/lib/check.py` drift logic based on audit tail `after_sha256` should be downgraded or deleted because there is no longer an audit oracle.

**Test fallout.** Delete `tests/phase_state/test_state_trust_preflight.py` wholesale. Delete `tests/phase_preflight` state-trust taxonomy tests. Delete or rewrite `tests/cli/test_status.py::test_status_preflight_rejects_tampered_state` and `test_status_fails_closed_when_state_audit_mismatch`. Rewrite phase approve/reopen tests that spy on state-trust preflight or expect tampered-state rejection; keep their lock-held, audit-row, identity, and state-mutation tests. Remove `skip_state_trust_preflight=True` from fixtures and tests once the parameter is gone.

**Order within.** #10 must follow #9 because `state_trust` depends on audit rotation / `after_sha` walkback. Within #10, remove call sites *before* deleting the module so import failures reveal all live dependencies cleanly. Gate after deletion with the `rg` query above.

**Risk + canary.** Risk is losing useful malformed-state diagnostics while deleting anti-tamper logic. Rollback should *not* restore audit-oracle trust; if canary failures show users need diagnostics, add a tiny JSON/schema validator in `phase_state` or `phase_preflight`, not `state_trust`. Canary: a manually corrupted `.scratch/phase-state.json` fails where it is parsed, with a clear parse / schema error, not a trust / audit mismatch.

## #11 — Trim `phase_txn.py` recovery machinery

**Targets.** Remove journal / recovery-matrix machinery from `scripts/lib/phase_txn.py`: `JOURNAL_NAME`, `TMP_NAME` (if the atomic helper covers tmp internally), `RecoveryResult`, `_state_sha_of_disk()`, `_file_sha()`, `_audit_tail_partial_write()`, `_audit_tail_entry()`, `_audit_tail_txn_id()`, `_MalformedJournal`, `_read_journal()`, and `recover()`. Remove recovery-matrix fixtures under `tests/fixtures/crash/`, plus `tests/crash/test_recovery_matrix.py` and `tests/phase_txn/test_recovery_matrix.py`.

**Refactor.** Keep `TxnRequest`, `_canonical_bytes()`, `_sha256()`, `_new_txn_id()`, `_check_lock()`, `_TXN_VERBS` (if tests still align audit verbs), and `commit_transaction()`. Rebuild `commit_transaction()` around ADR-0004: require live `phase_lock`, canonicalize `after_state`, atomic-write `phase-state.json` using existing `atomic_io` / `durable_fs` primitives, append plain audit row with `txn_id` / `before_sha256` / `after_sha256`, return `txn_id`. No journal, no recovery replay, no audit-tail partial-write oracle. Expected `phase_txn.py` size: ~150–220 LOC.

**Call-site cascade.** Callers of `commit_transaction()` in `phase_approve.py`, `phase_reopen.py`, tests, and phase CLI should keep working if `TxnRequest` and the return value stay stable. Any CLI path invoking `phase_txn.recover()` must be removed or rerouted; likely candidates are lock / state-repair docs and any harness lock-recover or crash-recovery command paths surfaced by tests. `scripts/tests/test_phase_txn_audit_tail.py` dies because `_audit_tail_partial_write()` dies.

**Test fallout.** Delete recovery-matrix tests and fixtures. Delete `tests/phase_txn/test_fixture_round_trips.py`. Delete `scripts/tests/test_phase_txn_audit_tail.py`. Rewrite `tests/phase_txn/test_commit.py`: keep tests for lock required, released lock refused, canonical state write, fresh insert, audit entry has `txn_id` / `before` / `after` hashes, and durable write ordering only to the extent ADR-0004 requires atomic write before/with audit append. Remove tests requiring journal fields, journal left behind on replace failure, fsync order tied to the five-step ceremony, and roll-forward / rollback behavior.

**Order within.** #11 comes last because #8 / #9 remove chain assumptions and #10 removes state-trust's reliance on `after_sha256` as an oracle. Within #11: first rewrite `tests/phase_txn/test_commit.py` to the ADR-0004 contract; then delete recovery-matrix tests / fixtures; then simplify `commit_transaction()` while preserving `TxnRequest`, `_canonical_bytes()`, `_sha256()`, `_TXN_VERBS`, lock validation, `txn_id`, and before/after hashes; then remove `recover()` and private audit-tail / journal helpers; finally clean docs and grep gates for `journal`, `recover()`, `RecoveryResult`, and recovery-matrix language. Explicit pre-merge gate: approve / reopen / phase-set must still mutate state once, under lock, with one plain audit row.

**Risk + canary.** Riskiest strip because phase mutation is load-bearing. Risk is corrupting the core workflow state-transition path, not losing the recovery matrix. Rollback should restore only the last known-good `commit_transaction()` behavior, not `state_trust`, `audit-chain`, or the full recovery oracle. Canary signals: missing / released lock still refuses; normal commit writes canonical JSON; audit row contains verb, `txn_id`, `before_sha256`, `after_sha256`, actor / context fields; injected write failure leaves either old valid JSON or new valid JSON, never a partial file; approve / reopen integration tests still pass. If failure-injection shows ambiguity around state-vs-audit ordering, keep a tiny temp-file atomic-replace path and drop audit recovery rather than reintroducing journal replay.

## TL;DR

Delete `audit_chain`, make `audit.py` boring JSONL, delete `state_trust`, and trim `phase_txn` to atomic state write + primary lock + diagnostic audit row. The hard boundary is ADR-0002 / 0004 / 0005: no attacker, no tamper oracle, no hash chain, no recovery matrix; keep only the primitives that prevent normal internal-tool damage from concurrent runs or local write crashes.
