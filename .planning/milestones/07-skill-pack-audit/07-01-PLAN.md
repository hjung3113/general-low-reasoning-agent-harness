# Milestone 07 — Skill-pack audit

Cull only with evidence. Co-designed with codex via cmux on 2026-05-23. Not a vibes cull — add an audit gate first, then delete only manual-only packs that fail all of: default selection, DB selection, meaningful tests/docs, real target story.

## Likely delete set (subject to audit-gate evidence)

Seven manual-only `workflow-*` packs: `workflow-data-analysis`, `workflow-data-processing`, `workflow-tdd`, `workflow-debugging`, `workflow-code-review`, `workflow-skill-authoring`, `workflow-security-review`.

**Codex caveat (do not skip)**: `workflow-tdd`, `workflow-debugging`, `workflow-code-review` are *risky* despite being manual-only — they are broadly useful and may be real operator choices. Require an explicit keep/delete decision after the audit report, not a default-delete pass.

**Do not cull**: `workflow-core`, `workflow-etl`, `workflow-db-context`, `workflow-web-development`, or any `tech-*` pack currently selected by profile/DB defaults.

## #16 — Skill-pack audit

**Targets / new files.** For each culled pack: delete `harness/skill-packs/<pack>/.../SKILL.md`, remove top-level `harness/manifest.json` `packs.<pack>` metadata, remove every `manifest.files[]` entry with `pack: <pack>` / `owner: pack:<pack>`, remove tests that only prove the deleted pack installs, and remove docs/examples naming it as supported. **Do not** delete `workflow-core` subskills even if some are meta-ish; it is the generic default and is load-bearing.

**Refactor.** Add a small audit helper rather than hand-grepping forever: `scripts/audit_skill_packs.py` or a test-local helper that reads `harness/manifest.json`, `scripts/lib/profiles.py`, and `harness/skill-packs/`. It should print per-pack evidence columns and **fail** if:
- a manifest pack has no files
- a skill-pack dir is absent from manifest
- a default pack is missing
- a pack is manual-only with no explicit `usage_status` / `real_target_story` metadata

Before→after pack count: 18 → 11 if the seven manual-only workflow packs are culled; 18 → 18 if retained by adding real target stories. Avoid "rewrite" of pack contents unless a kept pack has category drift; this milestone is cull or justify, not editorial polish.

**Call-site cascade.** Update `scripts/lib/profiles.py`: `_PROFILE_DEFAULT_PACKS` and `_DB_PACKS` probably stay unchanged because risky packs aren't default/DB-selected. Update `scripts/lib/manifest.py::KNOWN_PACKS` to remove culled names. Update `harness/manifest.json` packs and files. Update `scripts/tests/test_harness.py` around all-pack install tests, especially "quality workflow packs" assertions for culled packs. Regenerate `docs/ARTIFACTS.md` after M6 landed, since pack counts and installed file tables change.

**Test fallout.** Delete tests whose only job is proving deleted packs install or contain phrases (the "quality workflow packs install low-reasoning contracts" assertions for culled packs). Rewrite the "requested tech and workflow packs install as composable skills" test to use only retained manual packs, or split into "all known packs from manifest install" generated from manifest so it tracks culls automatically. Keep profile/default tests for `generic`, `dotnet-etl`, `python-etl`, `react-web`, `mssql`, `postgresql`. **Add a new audit test**: every pack is either selected by a profile/DB default or has explicit manifest metadata proving manual support (e.g. `usage_status: supported-manual` plus a short `target_story`).

**Order within.** Three phases with gates:

1. **Add the audit report/check** with no deletions. Baseline exposes exactly which packs are unsupported. Gate: manifest loads, all packs accounted for.
2. **Classify packs.** Defaults/DB packs = keep by default; manual-only packs need tests/docs/target story OR deletion.
3. **Cull manual-only packs one group at a time**, lowest-risk first:
   - Group A: `workflow-skill-authoring`, `workflow-security-review`
   - Group B: `workflow-code-review` (explicit keep/delete decision required)
   - Group C: `workflow-data-analysis`, `workflow-data-processing`
   - Group D: `workflow-tdd`, `workflow-debugging` (explicit keep/delete decision required)
   
   Gate after each group: manifest loads, unknown-pack rejection still works, all retained packs install.

Final step: regenerate `docs/ARTIFACTS.md`.

**Risk + canary.** Main risk: deleting a manually requested pack that is useful but invisible to defaults/tests. Canary signals: `harness init --profiles generic` still installs `workflow-core`; ETL profiles still install `workflow-etl` plus the right tech pack; DB options still add `workflow-db-context` plus DB tech pack; `--packs <retained-pack>` installs every retained pack; `--packs <culled-pack>` fails with a clear unknown-pack error; generated `docs/ARTIFACTS.md` shows the new pack count.

## TL;DR

Don't vibes-cull. Build the audit gate first, classify packs by evidence, then delete only manual-only packs with no default selection, no DB selection, no meaningful tests/docs, and no real target story. Likely delete set is seven manual-only workflow packs; `workflow-tdd`, `workflow-debugging`, `workflow-code-review` deserve an explicit final keep/delete decision before removal.
