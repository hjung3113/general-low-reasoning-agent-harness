# Milestone 05 — Approval simplification

Turn approval into what ADR-0001 / ADR-0002 say it is: a manual human pause with attribution, not an authorization system. Strip override-identity, fingerprint checks, approver allowlists, nonce leftovers, and sanitizer machinery built for adversarial provenance. Keep TTY, `[y/N]` prompt, `--by` / gitconfig attribution, state stamp, and a plain audit row.

Co-designed with codex via cmux on 2026-05-23. Assumes Milestone 4 has landed (`state_trust.py` deleted, `audit.py` simplified, `phase_txn.py` trimmed).

## Scope

Sequence: **#12 → #13**, with a hard gate between.

Gate after #12: `rg "override_identity|override-identity|override_reason|gitconfig_mutated_post_install|git_user_email_at_install_sha256|skip_state_trust_preflight|nonce_id" scripts tests docs` returns only migration / graveyard refs. Approve flow still refuses non-TTY with exit 17.

Gate after #13: `rg "approvers|approver-email|approver_not_in_install_record|install-record approvers|membership" scripts tests docs` returns only migration / graveyard refs. Fresh install writes the smaller install-record; legacy `approvers[]` in an existing record is silently ignored (forward-compat for installed targets).

**Refactor.** `phase_approve.py` drops from post-M4 ~450–500 LOC to ~220–280 LOC. Audit row always uses `by=resolved`, `by_source=gitconfig_auto|explicit_by_flag`, `confirmation_kind=soft_tty`, `proof_class=soft_tty|smoke_bypass`, `tty`, and `response`. No `override_identity`, no `resolved_email` inside args, no fingerprint subreason. Fix the current output bug while here: printed `approved_by` should match the stamped identity (`resolved`).

**Call-site cascade.** Update `scripts/lib/phase_cli.py::cmd_phase_approve()` to stop passing `nonce_dir` and `skip_state_trust_preflight`; rewrite the docstring that still claims install-record membership / state-trust. Update `scripts/tests/test_phase_cli.py::_run_approve()` to stop creating nonce dirs and stop passing compat flags. Update `tests/integration/test_phase_approve_speed_bump_e2e.py`, `tests/phase_approve/conftest.py`, `tests/phase_approve/test_speed_bump_prompt.py`, `tests/phase_approve/test_approve_provenance.py`, and `tests/phase_approve/test_override.py` to the smaller API. `phase_reopen.py` has similar identity prose — touch only if shared helpers move; do not expand M5 into reopen behavior unless imports break.

**Test fallout.** Delete `tests/phase_approve/test_override.py` wholesale (tests the branch being removed). Delete tests for gitconfig fingerprint mismatch, override reason missing/invalid/too long, override identity replacing audit `by`, override sanitizer, nonce compatibility, and state-trust preflight if M4 didn't already remove them. Rewrite provenance tests to assert only: non-TTY refuses with exit 17, gitconfig identity is used, `--by` overrides gitconfig, env vars do not influence identity, approve stamps state, audit row has plain soft-TTY provenance, idempotent second approve is a no-op, lock is held during mutation. **Risk + canary.** Risk is accidentally weakening the human checkpoint by removing TTY / prompt behavior while deleting identity theater. Canary signals: non-TTY approve still exits 17; `HARNESS_BY_TRUST` / env injection still has no effect; `--by bob@example.com` stamps `approved_by=bob@example.com`; gitconfig fallback works; cancel writes no state / audit row; successful approve writes exactly one state mutation and one plain audit row. Rollback restores only the simple resolver / prompt path, not override identity, fingerprint checks, or state-trust hooks.

## #13 — Replace approver allowlist with first-run TTY confirm

**Targets.** Delete the leftover allowlist model: `scripts/lib/phase_preflight.py::approvers_emails()`, `FIX_APPROVER_MEMBERSHIP`, tests for `approvers_emails`, install-record `approvers[]` production in `scripts/lib/install.py:164`, `resolve_approver_email()` / `_sanitize_approver_email()` if they exist only for allowlist bootstrap, CLI `--approver-email` support, docs saying "only listed approvers may approve," and install-record bootstrap audit fields like `approver_count`. Replace with `installer_email` / `confirmed_by` / `confirmed_at` (or equivalent first-run attribution), **not** an authorization list.

**Refactor.** `install.py` stops asking "who may approve later?" and instead records "who initialized this harness?" after a TTY confirmation if the flow is interactive. Expect `install.py` to shed ~80–140 LOC depending on how much approver-bootstrap code and CLI plumbing exists. `phase_preflight.py` shrinks to generic helpers only (`now_iso_z()`, `default_gitconfig_email_lookup()`, `load_install_record()` if still shared). Install-record schema becomes smaller and honest: `version`, `installed_at`, installer identity / source, selected profile / packs / manifest metadata, optional `first_run_confirmed: true`. **No `approvers`, no membership, no gitconfig fingerprint.**

**Call-site cascade.** Update `scripts/lib/install.py::write_install_record()` + `install()` call sites that pass `approver_email` / `approver_bootstrap_source`. Update CLI parser wherever `--approver-email` is defined (likely `scripts/harness.py` or `phase_cli.py`-adjacent setup). Update `scripts/lib/phase_approve.py` and `scripts/lib/phase_reopen.py` to require only install-record presence if they still need it; **they must not read `approvers`**. Update upgrade / adoption tests if they assert install-record shape. Update docs: `docs/CLI.md`, `docs/WORKFLOW.md`, `docs/INSTALL-MODEL.md`, `docs/error-code-map.md`, and any artifact contract docs created in M3 / M4.

**Test fallout.** Delete tests for `approvers_emails()` and `--approver-email` membership bootstrap. Rewrite install tests that expect `approvers[]` to expect `installer_email` or `confirmed_by` instead. Edit phase-approve / phase-reopen fixtures to stop writing `approvers` arrays; fixtures only need a minimal valid install-record. Keep tests proving missing install-record refuses if that remains the contract. Add **one focused install test**: interactive / TTY first-run writes install-record with first-run-confirmation fields; noninteractive install either requires an explicit `--noninteractive` flag or records source clearly without pretending it is approval authorization.

**Order within.** After #12 lands, strip tests and fixtures first so failures point to real schema users. Then change install-record writer, then parser flags, then shared preflight helpers, then docs. **Do not touch upgrade / adoption semantics** unless they fail because they copy or validate `approvers[]`; in that case, make them tolerate absence and preserve unknown fields only if the current install-record contract requires forward compatibility. Gate at the end (see above).

**Risk + canary.** Risk is breaking existing installed targets whose `install-record.json` still contains `approvers[]` or whose tests build that shape. The new code should **tolerate** old records by ignoring `approvers[]`, not failing them. Canary signals: fresh install writes a smaller install-record; existing record with legacy `approvers[]` still allows phase approve; missing install-record still gets a clear repair message; docs no longer imply two-person or membership control; `harness phase approve` remains self-approval by TTY speed bump.

## TL;DR

Strip approval down to the human checkpoint it actually is. `--override-identity`, gitconfig fingerprinting, the approvers allowlist, the bootstrap nonce machinery, and the adversarial sanitizers all die. What stays: TTY refusal for non-TTY, `[y/N]` prompt, `--by` / gitconfig identity resolution, a single state mutation under lock, a single plain audit row.
