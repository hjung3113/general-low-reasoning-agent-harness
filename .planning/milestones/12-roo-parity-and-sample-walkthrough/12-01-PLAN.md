## Adversarial Review (2 roles × 3 lenses)

**Role A — First-time user (low-context engineer):**
- L1: Can they find the walkthrough from README within 30s of cloning?
- L2: Is each step's "user prompt" copy-pastable verbatim, or does it require context they don't have?
- L3: Does the walkthrough show what to do **when something fails** (failed gate, denied write), not only the happy path?

**Role B — Roo Code adopter migrating from opencode:**
- L1: Are the Roo banners semantically identical to opencode (same FORBIDDEN/ALLOWED lists)? Drift = silent bypass risk.
- L2: Does the refusal template still point to the correct command chain (`harness phase set plan` → `harness phase approve` → `harness phase set execute`)?
- L3: Does Roo's `--chain`/`--auto` flag still work, or does the new banner block it?

**Mandatory low-reasoning lens:** Are the FORBIDDEN/ALLOWED file lists concrete enough that a low-reasoning model can pattern-match without inference? (e.g., "*.html, *.css, *.js" vs. "source files").

## Low-Reasoning Ambiguity Risks

- "FORBIDDEN this phase" must list extensions, not categories.
- Refusal template must be quotable verbatim (one block, no placeholders requiring inference beyond `<X>`/`<Y>`).
- HTML walkthrough step ordering must match `harness next --prompt` natural progression — no skipped steps.
