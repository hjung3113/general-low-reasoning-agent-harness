# T1-1 — `check --worktree` Wired at the Workflow Boundary

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (preferred) or `superpowers:executing-plans`. Track each step via its `- [ ]` checkbox. Do not skip tests.

**Spec row:** `docs/superpowers/specs/2026-05-16-hardening-slice-design.md` §7 T1-1 ("`check --worktree` wired as required step at the workflow boundary chosen by ADR-003a") + §7 per-row notes "T1-1 (`check --worktree` wiring)" + §8 ("T1-1 sequences after T0-3") + §10.4 ("Adapter mirroring … is part of T0-3 and T1-1").

**ADR:** `docs/adr/2026-05-16-hardening-bundle.md` ADR-003a (CLI contract; post-amendment commit `880334f` `docs(adr): assign exit code 4 to SCOPE_VIOLATION` LIFTS the original reservation and assigns code 4 here).

**Contract:** `.planning/phases/02b-hardening/CONTRACT-PIN.md` §1 (consumes `EXIT_SCOPE_VIOLATION` from `scripts/lib/exitcodes.py` created by T0-A and populated by T0-3; consumes `STATE_FILE_PATHS` from `scripts/lib/operational_paths.py`), §3 (flat tests), §4 (exit code 4 = `EXIT_SCOPE_VIOLATION` confirmed by ADR amendment `880334f`), §5.5 (check.py merge order: T0-2 → T0-4 → T1-1; T1-1 rebases on T0-4 before merging), §7 (ledger L16 in FIRST commit).

**Goal:** When an actor (human or low-reasoning agent) attempts to commit work that touches files outside the live `allowed_paths` (or inside `blocked_paths`), the system fails LOUDLY at TWO mutually-reinforcing boundaries: (1) `git commit` is rejected by a pre-commit hook calling `harness check --worktree`; (2) the adapter `execute` command files instruct the agent to run `harness check --worktree` before invoking commit. Failures name the violating files, cite `docs/protocol-spec.md#scope-enforcement`, and suggest "edit `allowed_paths` or move the change out".

**Architecture:** No new top-level modules. `scripts/lib/worktree.py::check_worktree_paths()` is the single enforcement primitive (T0-2 fixed its glob semantics; T0-3 stabilised its exit-code contract). This row WIRES that primitive into:
- a new shell hook `harness/skeleton/clean/.githooks/pre-commit-scope` (installed by `harness install --pre-commit`) that shells out to `python3 scripts/harness.py check --worktree` from the repo root.
- the two adapter `execute` command files, which already cite `check --worktree` informally; this row makes it a numbered, mandatory pre-commit step with explicit retry-on-failure guidance.
- a documented uninstall path: `harness uninstall --pre-commit` and the manual `git config --unset core.hooksPath` fallback.

**Tech stack:** Python 3 stdlib only for CLI changes; POSIX `sh` for the hook (no bash/zsh idioms). `unittest` for test coverage.

**Out of scope (per spec D1, §4 non-goals):**
- GitHub Actions / any CI wiring outside the local repo.
- `pre-push` / `pre-merge-commit` / `commit-msg` hook wiring (this row owns `pre-commit` only).
- Wiring scope enforcement into non-lifecycle adapter commands (§7 R-3 quarantines them).
- Skill-pack content rewrites (T1-S owns that).
- Adapter command symmetry beyond the `execute` verb (§10.4 explicitly: lifecycle four only).

**Exit-code reservation:** ADR-003a originally reserved code 4 for "schema-version refusal." That reservation was LIFTED by ADR amendment commit `880334f` `docs(adr): assign exit code 4 to SCOPE_VIOLATION`. This row consumes `EXIT_SCOPE_VIOLATION = 4` from `scripts/lib/exitcodes.py` (declared by T0-A; populated by T0-3) — NO numeric literal `4` in T1-1 source per CONTRACT-PIN §1 rule. Tests assert `exitcodes.EXIT_SCOPE_VIOLATION == 4` rather than the raw int. Exit 0 on clean. Exit 1 reserved for `argparse` / catastrophic. The claim and ADR amendment are recorded in `docs/protocol-spec.md` under §scope-enforcement (Task 6).

## Conventions

- **Hook filename:** `pre-commit-scope` in the skeleton tree. The installer either (a) symlinks `.git/hooks/pre-commit` → `pre-commit-scope` when `.git/hooks/pre-commit` is absent, or (b) appends a documented marker block to an existing `.git/hooks/pre-commit` (idempotency key: `# HARNESS:scope-check-begin` / `# HARNESS:scope-check-end`). The marker-block branch must use the same managed-block discipline as `scripts/lib/managed_block.py` (re-use that module, do not reinvent).
- **Hook output:** on violation, print to stderr:
  ```
  harness: scope violation (exit 4)
  Files outside allowed_paths:
    <path1>
    <path2>
  Remediation:
    - Move the change out of the commit, OR
    - Add the path/glob to .scratch/phase-state.json `allowed_paths`, OR
    - Remove a matching entry from `blocked_paths`.
  See docs/protocol-spec.md#scope-enforcement.
  ```
- **No `git config core.hooksPath` writes by the installer.** Spec convention: leave user's `core.hooksPath` alone; install into `.git/hooks/` directly so uninstall is a single `rm`.
- **`check --worktree` exit-0 ambiguity:** when `phase-state.json` is missing or `changed_path_gate_allows_state()` returns False (e.g., phase=plan), the hook exits 0 (cannot enforce; not a violation). This is intentional and documented; a separate ADR (out of scope here) may tighten it.

  ```sh
  #!/bin/sh
  # HARNESS:scope-check-begin
  # Installed by `harness install --pre-commit`. See docs/protocol-spec.md#scope-enforcement.
  # Resolve repo root robustly — git invokes hooks from arbitrary cwd subtrees.
  REPO_ROOT=$(git rev-parse --show-toplevel 2>/dev/null) || {
      echo "harness pre-commit hook: not inside a git repo; skipping scope check (non-fatal)" >&2
      exit 0
  }
  if [ -f "$REPO_ROOT/scripts/harness.py" ] && [ -f "$REPO_ROOT/.scratch/phase-state.json" ]; then
      (cd "$REPO_ROOT" && python3 scripts/harness.py check --worktree) || exit $?
  else
      echo "harness pre-commit hook: scripts/harness.py or .scratch/phase-state.json not found at repo root; skipping scope check (non-fatal warning)" >&2
  fi
  # HARNESS:scope-check-end
  ```
