- Update `docs/protocol-spec.md` (if present) or `docs/skeletons/`-equivalent prose to point at ADR-002 grammar; no new doc files.

## Production Tasks (only after each red test exists)

The order is "make one test green at a time", but the underlying production edits cluster into the following commits. Each commit must keep the full test suite green.

### Task 1 - Activate `fnmatch.fnmatchcase` and add grammar-conformant matcher

File: `scripts/lib/worktree.py`.

1. Replace the dead `import fnmatch` with `from fnmatch import fnmatchcase` and use it.
2. Add a private helper `_glob_match(path: str, pattern: str) -> bool` that:
   - Splits pattern and path on `/` into segments.
   - Returns False if segment counts differ (this enforces the "no-`/`-crossing" rule for both `*` and `?` and the "treat `**` as `*`" rule).
   - For each segment pair, calls `fnmatchcase(path_segment, pattern_segment)`.
   - Returns True iff every segment-pair matches.
3. Add a private helper `_has_glob_metachars(pattern: str) -> bool` returning `any(c in pattern for c in "*?[!]")`.
4. Rewrite `matches_any`:

   ```python
   def matches_any(path: str, patterns: Iterable[str]) -> bool:
       for pattern in patterns:
           normalized = normalize_path(pattern)
           if normalized.endswith("/"):
               if path.startswith(normalized):
                   return True
               # also try as glob "<dir>/*" for single-segment children
               if _glob_match(path, normalized + "*"):
                   return True
           elif path == normalized:
               return True
           elif _has_glob_metachars(normalized):
               if _glob_match(path, normalized):
                   return True
       return False
   ```

5. `_glob_match` MUST raise `ValueError` (or a typed `ScopePatternError` defined in `scripts/lib/worktree.py`) on a malformed pattern. The current Python stdlib `fnmatchcase` does not raise on `"[abc"` (it silently treats the bracket as a literal). To satisfy test 14, add an upfront validator `_validate_pattern(pattern)` that scans for an unterminated `[` and raises `ScopePatternError` with the pattern in the message. Run the validator from `matches_any` (NOT from `_glob_match`, so prefix-only patterns are never validated against glob rules).

### Task 3 - G3-B breakage scanner

Add a new function in `scripts/lib/worktree.py`:

```python
def scan_for_glob_literal_collisions(
    target: Path,
    state: dict[str, object],
    stream,  # typically sys.stderr
) -> None:
    """ADR-002 G3-B: warn when a globbed entry has a literal file/dir at the same path."""
```

Behavior:

- Iterate `("allowed_paths", "blocked_paths")` -> entries.
- For each entry containing any of `* ? [ ! ]`, compute `literal = target / normalize_path(entry).rstrip("/")` and check `literal.exists()`. If true, write the warning line specified in the ADR (verbatim) to `stream`.
- Use a `seen: set[tuple[str, int]]` to enforce one-warning-per-(field, index) per invocation (test 13).
- Never raise; never affect exit code.

Wire the scanner into `check_changed_paths` and `check_worktree_paths` immediately after the `state = json.loads(...)` line and before the gate check. Pass `sys.stderr` as `stream`. (Touching `check.py` is NOT required for this hook; both entry points already live in `worktree.py`. If `scripts/lib/check.py:CheckRunner` also loads the state for unrelated reasons and we want a single call site, defer that consolidation to a follow-up — not in this slice.)

## Risk Register

- R1 - **Hidden glob-shaped entries in user repos** that previously zero-matched will start matching. Mitigation: G3-B warning + release note in CHANGELOG. Severity: medium.
- R2 - **`fnmatchcase` does not treat `/` as a separator**, so naively calling `fnmatchcase(path, "*.md")` would match `"foo/bar.md"`. Mitigation: segment-split in `_glob_match`. Tests 3, 4, 5 cover this. Severity: high if not caught; mitigated by test design.
- R3 - **Unterminated bracket** is silently swallowed by stdlib. Mitigation: upfront `_validate_pattern`. Test 14 enforces. Severity: medium.
- R4 - **Breakage scanner false positives** if a user really meant the literal path and expects the scanner to silence. Mitigation: warning text explicitly tells the user to escape or remove the metacharacter; warning is not an error. Severity: low.
- R5 - **Trailing-slash double-branch** (`docs/` matched both as prefix AND glob `docs/*`) could over-match. Mitigation: tests 2 and 15 lock the behavior; both branches are equivalent for trailing-slash entries by construction. Severity: low.
