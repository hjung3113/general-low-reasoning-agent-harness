# Future — undecided / undated

**Status**: parking lot. Ideas that are technically reasonable but not committed to a version. Each note records the trigger condition that would promote it to a real version.

## Why not assign a version?

Some items depend on conditions outside the maintainer's control (e.g. corp model gets stronger; OpenCode adds positional args; user demand for multi-user). Assigning a version forces scope; this folder admits the timing is unknown.

## Index

- `2026-05-17-mcp-server.md` — MCP server integration. Promotion trigger: corporate / stronger model available, OR community demand to expose harness as MCP tool.

## Promotion rules

1. When a future item is about to start: move the file to a new `vX.Y.0_todo/` folder, write a README there, link from this folder's README to indicate the promotion.
2. When an item is definitively rejected: append a "REJECTED" section to the file with reason and date; keep the file for history.
