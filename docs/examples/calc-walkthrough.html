★Goal

Build a tiny HTML calculator (four operators + parentheses) using opencode (zai/glm-4.5-flash, weak reasoning) inside a fresh harness-managed project. The walkthrough captures every prompt the user typed, what the agent did, and how repo state changed — so a first-time reader can see the full loop end-to-end, including the moment the workflow blocks a premature code request.

Why follow this? Phase gates only protect you if you actually use them. Skipping orientation and approval is the failure mode this harness was built to prevent.

0Install the harness into a fresh project

terminal — no phase yet

$ python3 /path/to/general-low-reasoning-agent-harness/scripts/harness.py \
    install --target . --pre-commit

5User asks for code too early — the gate fires

phase = plan, approved = false → REFUSE

User prompt

이제 계산기 실제로 만들어줘. 단순하게.

Agent action — refusal template (verbatim from AGENTS.md guard)

현재 phase=plan, approved=false 라 source 파일 작성 불가.
다음 명령 chain 을 차례로 실행해야 함:

  harness phase set plan              # if not already plan
  # write PLAN.md, then in a real terminal:
  harness phase approve               # TTY-only human approval
  harness phase set execute

그 후에 source 파일 작성 가능. 지금은 다음 동작 추천:
$ python3 scripts/harness.py next --prompt
[현재 워크플로우 상태 — 매 동작 전에 확인]
- phase: plan
- approved: False
- forbidden writes this phase: *.html, *.css, *.js, ...
This is the critical moment. Without the AGENTS.md persistent guard + the per-command STOP banners in .opencode/commands/*.md, a low-reasoning model will obey the user and write HTML files immediately. Defense in depth: prompt-layer (banner + refusal template) + post-hoc (harness check drift detection) + commit-time (pre-commit hook exit 4).

6User approves from their own terminal

phase = plan → approved → execute

Approval is intentionally TTY-only — the agent cannot self-approve. The user runs:

$ harness phase approve
{ "ok": true, "approved": true, "approved_by": "user@example.com",
  "approved_at": "2026-05-24T..." }

$ harness phase set execute
{ "ok": true, "phase": "execute" }

State delta

approvedfalse → true
phaseplan → execute
+ stampedapproved_by, approved_at (audit trail)

7Execute, verify, and commit

phase = execute, approved = true

User prompt (re-issued)

이제 계산기 실제로 만들어줘. 단순하게.

Agent action

→ Write index.html         # inside allowed_paths ✓
→ Write style.css          # inside allowed_paths ✓
→ Write calc.js            # inside allowed_paths ✓

$ harness check
ok — phase=execute, approved=true, allowed_paths matched

$ git add index.html style.css calc.js
$ git commit -m "feat(M1): basic calculator UI"
# pre-commit hook runs: harness check --worktree → exit 0
[main abc1234] feat(M1): basic calculator UI
 3 files changed, 142 insertions(+)
Happy path. Every write was inside allowed_paths, the commit cleared the pre-commit hook on exit 0, and the audit log records who approved when. To start M2, the agent must drop back to phase=plan and re-approve.

If a write strays outside allowed_paths

$ git add scripts/secret_helper.py    # NOT in allowed_paths
$ git commit -m "..."
# pre-commit hook: exit 4 (scope violation)
Phase boundary violation: scripts/secret_helper.py not in allowed_paths.
Fix: (a) git restore --staged scripts/secret_helper.py, OR
     (b) return to plan, expand allowed_paths, re-approve, re-enter execute.
